# 音色编织（Timbre Weave）

**把一坨混在一起的 midi 音符，按"演奏合理性"重新分配到你自己挑选的乐器上。**

---

## 这个软件是干什么的

它服务于 **MusicDoll** 系列的动画制作流程，解决的问题出现在这样一个环节上：

1. 你手上有音频，用 **MSST** 之类的方法把人声、钢琴、吉它、打击乐、其它乐器**分成了几组音频**；
2. 其中"其它乐器"那一组里，往往还是**一堆管弦乐器混在一起**（比如弦乐群 + 木管 + 铜管）；
3. 拿它去做音频转 midi——**现有的识别方法只对钢琴、吉他、打击乐、人声这几种有限音色有效**，
   对管弦乐器分不开；
4. 结果是：**你得到了一条（或几条）midi 轨，里面是各种乐器不同音色、但全部混在一起的音符。**

到了这一步，通用的识别手段已经帮不上忙了，所以需要这个软件介入。

它做的事情是：**读出那堆混在一起的音符，按"这些音交给哪件乐器演奏最合理"把它们重新分成多条干净的乐器轨**，
输出一个多轨 midi 文件，供 MusicDoll 后续生成动画使用。

### 它不做什么

- **不做音频识别**，也不做音源分离——它只处理已经从音频转出来的 midi 音符。
- **不做配器建议**，不会告诉你"这里该用双簧管"。用什么乐器，是你听完音频之后自己定的。
- **输出的不是给人演奏的乐谱**。它是给后续动画流程用的驱动数据，所以不处理弓法、把位、
  移调记谱这些谱面问题（输出的音高一律是**实际发声音高**）。
- **不含和声乐器**（钢琴、吉他、竖琴等）。这些乐器一次能同时奏出很多音，
  和本软件的"每件乐器能同时奏几个音"模型不是一回事。
- 不做跨乐句的旋律连贯性——同一个乐句的前后两个音可能被分给不同乐器。

---

## 使用前提：先听，再动手

**这是整个流程里最重要的一步，软件替代不了。**

先仔细听那段音频，判断出：

- **大概用了哪些乐器**（是弦乐群？还是木管 + 圆号 + 弦乐？）
- **每样大概几件**（一把小提琴还是一群？两支长笛还是一支？）

把你听到的结果，翻译成"我要用这个软件分给哪些乐器、各几件"，再去操作软件。
听错了，分出来的结果自然不合理——软件只会忠实执行你的选择。

## 使用流程

启动后界面分三栏：**左边选源文件，中间挑乐器，右边执行看报告**。

### 第一步：选源 midi

在左栏「源文件」里点 **选择 MIDI 文件**，选中那条混在一起的 midi，
再点 **扫描轨道**。下方「轨道」卡片会列出这个文件里的所有轨道（轨号 / 轨道名 / 音符数）。

### 第二步：勾选参与分配的轨道

在轨道表最后一列 **作为源轨** 打勾，把"需要被拆分"的轨道选上。可以多选——
多条轨上的音符会被当成**同一池子**一起参与分配。

> 提示：源文件里如果有你不想动的轨（比如已经分好的钢琴轨），**不要勾它**。

两个读取选项一般不用改：

| 选项 | 说明 | 什么时候要改 |
| --- | --- | --- |
| **使用通道** | 默认"全部通道"。 | 如果同一条轨里用不同通道叠了多组乐器，可以只选其中一个通道。 |
| **量化** | 默认"1/16 拍"：起点相差不到 1/16 拍的音符算"同时发声"。 | 想让判定更严格就选更小的档位；选"不量化"则要求起点完全相同。 |

### 第三步：挑乐器（编制）

在中间「编制」栏里挑出你听出来的那些乐器：

- 上方有 **编制预设**（弦乐四重奏 / 木管五重奏 / 双管编制）可以一键填入，也可以点 **清空** 从零开始。
- 下面是 **乐器池**，按木管 / 铜管 / 弦乐 / 打击乐分组列出。点某一行前面的 **+** 就把它加进编制。
- **同一个乐器可以加多把**：比如两把小提琴就点两次"小提琴"，它们会自动命名成 `Violin 1` / `Violin 2`
  （已加的数量会显示成 `×2`）。
- 「已选乐器」卡片里能看到每件乐器的同时发音上限、可演奏范围、舒适区；点 **移除** 可以拿掉。

编制最多 **15 件**（和 midi 的可用通道数一致，每件乐器独占一个通道，互不干扰）。
界面上不用管通道，软件按序号自动排：第 1 件用 1 号、第 9 件用 9 号、第 10 件跳到 11 号
（10 号留给打击乐）、第 15 件用 16 号。

**挑几件合适？** 一个实用的判断方法：

> 数一数音频里**同时发声的音最多有几个**，再确保你的编制**总同时发音容量**不小于这个数。
> 弦乐每件最多 2 个音，管乐每件只能 1 个音。比如某处有 8 个音同时响，
> 用"两把小提琴 + 中提琴 + 大提琴"（容量 2+2+2+2 = 8）刚好够。

### 第四步：开始分轨

在右栏点 **开始分轨**。几秒后（大文件也通常在这个量级）会得到结果。

- 输出文件在**源文件同一个目录**下，名字是 `<源文件名>_split.mid`。
- **软件不会自动载入结果**，需要你自己去那个目录拿文件。

「候选池大小」滑块默认不用动。只有当你的源文件是**音频转出来的密集 midi**
（报告里"音符组数"远小于"读入源音符"，说明同时音极多）时，把它调大能拿到更准的结果。
调大只是更慢，不会算错。

### 第五步：看报告，不满意就改编制重跑

右栏下方是**「各乐器分到的音符」**表：每件乐器分到多少音符、占多少比例、实际用到什么音域、
有多少音是叠着拉/吹的、有多少音超出了它的舒适区。

<details>
<summary><b>点开看每个统计项的含义与应对办法</b></summary>

| 报告项 | 含义 | 数字大了怎么办 |
| --- | --- | --- |
| **读入源音符** | 从你勾选的轨道里读到了多少个音符。 | — |
| **音符组数** | 被判定为"同时发声"的音符组数。这个数远小于音符数，说明源文件同时音极多。 | 正常现象（音频转 midi 的典型特征）。 |
| **写回音符** | 实际写进输出文件的音符数（含叠音）。 | 明显小于读入数时，看下面几项。 |
| **八度折叠** | 有音符超出了所有所选乐器的音域，被移高/移低一个八度塞进音域内。 | 多说明音域覆盖不够，考虑加入音域更宽或更低/更高的乐器。 |
| **八度合并** | 同一时刻的重复音、以及互为八度的音被合并掉的数量。 | 很大是**正常的**——音频转 midi 会产生大量重复音与泛音，说明源文件本身很"脏"。 |
| **丢弃音符** | 编制**装不下**（同时音比总容量还多，折叠合并之后仍放不下）而丢掉的音符数。 | 加乐器。这是唯一会真的少音的情况。 |
| **强制安置（音域外）** | 某个音本来只有某件乐器能演奏，但那件乐器在同一时刻已经被占用了，只能硬塞给别的乐器，声音会不对。 | 加乐器，或给能演奏它的乐器多配几件。 |
| **叠音音符数** | 某件乐器在同一时刻要奏 2 个音。只会出现在弦乐（上限 2）上，**管乐永远是 0**。 | 这是"弦乐双音"，正常；不想听到就用更多弦乐乐器分摊。 |
| **超出舒适区（表内）** | 分给某件乐器的音里，有多少落在它"能演但不好听/不轻松"的音区。 | 多说明这件乐器被逼到了高把位或极端音区，考虑加同类乐器分摊。 |
| **池满被剪枝的组数** | 有这么多组的可选方案多到超出候选池上限，软件只保留了最好的那些。**不代表结果就是错的**，只是不保证是全局最优。 | 把「候选池大小」调大重跑。 |
| **共用通道** | 只有编制超过 15 件才可能出现（现在上限就是 15，所以正常不会出现）。 | 出现时说明配置异常。 |

</details>

## 关于"演奏合理性"

同一个音高，交给不同乐器，演奏难度完全不一样：长笛在低音区很闷、在高音区很亮；
单簧管低音区圆润、极高音区刺耳发紧；大提琴的低音弦很方便、高把位很难。
软件对每件乐器都登记了**可演奏范围**（硬边界，超出就完全不能给）和**舒适区**
（这段区间里最轻松、音色最好）。分配时它会综合考虑：

1. **同一时刻，绝不超出任何一件乐器的同时发音上限**（管乐只能一个音，弦乐最多两个）；
2. **只要存在"每件乐器都只奏一个音"的方案，就绝不出现叠音**；
3. 在此前提下，让每个音尽量落在**它所属乐器的舒适区**里，并且尽量少让乐器勉强叠音。

乐器池里的每件乐器都标注了它的舒适区是**有来源**（查过配器资料/乐器规格）还是**推断**的，
你可以据此判断哪些数字更可信。

## 常见问题

**问：分出来的结果有两个乐器重复演奏同样的音？**
同一时刻两个音高相同、分给了两件乐器，通常说明源文件在那个时刻确实有两个同音（比如弦乐群齐奏）。
软件会先做同音去重，剩下的就是源文件里真实存在的。

**问：为什么有些音被移高了/移低了八度？**
源 midi 里有超出你所选乐器音域的泛音或极低/极高音。软件会先尝试把它们折叠进音域内
（这就是"八度折叠"），而不是直接丢掉。

**问：管乐器那一行的"叠音音符数"是 0 才对吗？**
对。管乐物理上只能发一个音，软件绝不会让它拿到第二个音。如果你看到管乐有叠音，那是 bug，请反馈。

**问：可以只分给一件乐器吗？**
可以，但那就只是"过一遍"，没有分配的意义。实际使用建议至少 4 件。

**问：输出文件在 DAW 里看不到应有的轨道名？**
轨道名写进了 midi 的 `TrackName`，大部分 DAW 会显示；若没显示，检查导入选项里是否勾了"保留轨道名"。

## 运行与构建

```
# 从源码运行（需要 Rust 工具链）
cargo run

# 构建可执行文件
cargo build --release
```

工作目录需要包含 `asset/`（字体与词典）。用 `cargo run` 时在项目根目录执行即可。

界面支持**深色 / 浅色两套主题**（顶栏一键切换），以及**中英双语**（顶栏语言菜单）。
主题与语言选择会记住，存在工作目录的 `config.json` 里。

  为每条乐器轨指定角色、生成指法与动画。
- 本软件最早是从 string_flow 里的"弦乐四重奏自动分轨"演化出来的，
  现在把"四个固定声部"扩展成了"任意自选乐器编制"。
